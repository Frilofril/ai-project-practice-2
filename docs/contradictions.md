# Суперечності й прийняті рішення (тема 15)

| № | Суперечність або невизначеність | Моє рішення | Головна |
|---|---|---|---|
| 1 | Не визначено, чи може Співавтор редагувати статтю, коли вона вже відправлена «на перевірку» або має статус «опубліковано». | Поки стаття має статус «на перевірці» або «опубліковано», поля редагування для Співавтора заблоковані; щоб внести зміни, Співавтор натискає кнопку «Повернути в чернетки», що змінює статус статті на «чернетка» і знімає її з публічного каталогу. | ✓ |
| 2 | Невідомо, що відбувається зі зв'язками «багато до багатьох» між статтями та фракцією, якщо Головний редактор видаляє фракцію з довідника. | При видаленні фракції Головним редактором запис фракції та всі її прив'язки в проміжній таблиці зв'язків видаляються каскадно, а самі статті залишаються в базі даних без цієї мітки. | |
| 3 | Не визначено долю старого файлу зображення у сховищі Supabase Storage при завантаженні нової ілюстрації або видаленні чернетки. | При завантаженні нової ілюстрації до статті старий файл у Supabase Storage автоматично видаляється (перезаписується за тим самим шляхом), а при видаленні чернетки її файл також видаляється зі сховища. | |
| 4 | Невідомо, що стається з іншими відкритими скаргами на ту саму статтю, коли Головний редактор схвалює одну скаргу і стаття повертається в чернетки. | Коли Головний редактор приймає одну скаргу на статтю, сама стаття переходить у статус «чернетка», а всі інші відкриті скарги на цю статтю автоматично отримують статус «вирішено». | |
| 5 | Можливий стан гонитви, коли Головний редактор модерує статтю одночасно з редагуванням тексту Співавтором. | Оскільки редагування дозволено лише у статусі «чернетка», а модерація — лише у статусі «на перевірці», одночасна зміна неможлива: кнопка «Опублікувати» спрацьовує лише якщо поточний статус запису в БД дорівнює «на перевірці». | |
